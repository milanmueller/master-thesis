\subsection{The Practical Algebraic Calculus}

Logical circuits are the fundamental building blocks of all computers, their correctness is crucial for the safety and reliability of computer systems.
The Intel Pentium FDIV bug \todo{ref} is a classic historical example ... 

Since there are only finitely many possible input configurations for a logical circuit, correctness can in principle be proven by simply evaluating all possible inputs.
In practice however, this is often infeasible due to the exponential size of the search space.
For instance, a multiplier circuit for 64-bit integers has $2^{128}$ possible input combinations.
Assuming it takes one nanosecond to validate correctness of one input configuration, validating all possible input configurations would take more than $10^{22}$ years.

The practical algebraic calculus \cite{pac-2018} proposes a proof system to reason about the semantics of digital circuits using polynomial calculus.
As an example, consider \Cref{fig:2bit-multiplier} which shows a 2-bit multiplier.
For simplicity, we assume half adders with the usual semantic.\\

\subsection{Program Verification with Isabelle-LLVM}

One of the main challenges that every non-trivial software project is very likely to face eventually, is the existence of unforeseen errors.
Examples of such errors include out-of-bounds errors, use-after-free errors, or semantic errors in overlooked edge-cases, leading to crashes or otherwise unintended program behavior. \\
In critical systems, e.g. authentication engines or medical applications, such errors might lead to severe issues like exposure of sensitive data to bad actors\todo{Some example data breach}, or even pose danger to human lives\todo{The malfunctioning radiation device}.\\
To detect such errors preemptively, professional software development typically involves extensive testing of the developed product, ranging from simple unit tests to more sophisticated and automated approaches like fuzzing\todo{Reference}. \\
While testing is a powerful strategy for detecting errors, even simple programs might have state spaces too large to obtain full coverage of all possible inputs in testing.
This natural limitation of testing based quality assurance motivates the use of formal methods for verifying correctness of computer programs.

Formal verification of non-trivial, efficient programs is typically a hard task as programs will likely use complex data structures, like hashmaps, nested container structures, or tree-based structures, and a proper correctness proof must consider the exact semantics of such data structures, which significantly increases their complexity. 
In addition, many algorithms most efficient implementations rely on mutation of data in memory, typically seen in imperative languages like C/C++, which further complicates the construction of accurate formals models of such programs, compared to pure functional approaches, where immutability of data is an intrinsic invariant. 
The PAC checker Pastèque\cite{pasteque}, developed by Fleury, is formally verified by use of the interactive theorem prover Isabelle/HOL \cite{isabelle} with the Sepref framework \cite{sepref}, developed by Lammich.
Sepref addresses both of the aforementioned challenges in formal verification;
Firstly, separation logic is used to effectively reasoning about memory mutation.
Secondly, Sepref's refinement approach allows for splitting up correctness proofs into multiple steps of refinement, starting with abstract, idealized algorithms with are easier to reason on, and then concretizing the algorithms implementation in separate proof steps.
Sepref automates significant proportions of these steps.
The final, concrete programs can be exported to Standard-ML code. 
\refsec{sec:isabelle-refinement-framework} and \refsec{sec:sepref} present the fundamental concepts of working with Sepref.

The Isabelle-LLVM framework \cite{isabelle-llvm}, also by Lammich, can be seen as the Successor of Sepref. 
Instead of Standard-ML code, Isabelle-LLVM can be used to generate LLVM code, allowing for even more efficient verified programs.
\refsec{sec:isabelle-llvm} introduces the fundamental concepts for working Isabelle-LLVMs LLVM backend the separation logic defined on it. 

Migrating Pastèque from the Standard-ML backend to LLVM is the objective of this thesis. 
While the the main high-level algorithms remain unchanged, the concrete low-level implementation requires some preliminary work, which is the main workload in this thesis;
Pastèque relies on multiple precision integer arithmetic which is natively supported in the Standard-ML backend.
LLVM has no built-in support for multiple precision integers, I therefore use a native multiple precision integer implementation for Isabelle-LLVM by Spinei \todo{citation} with some extensions to support signed numbers, and translation from and to ascii-encoded strings, which is required for parsing and for printing error messages.
In addition, Pastèque relies on nestable lists, a hashmap and a hashset implementation for strings which are not directly available in Isabelle-LLVMs collection of data structures.
I therefore implement an opinionated nestable linked list, which copies elements where necessary (cf. \ref{sec:lists-with-tail-pointers}), and I implement generic (but tailored to Pastèque specifically) partial maps, hashmaps and hashsets.
