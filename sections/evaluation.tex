\section{Evaluation}\label{sec:evaluation}

This section discusses the evaluation of the migrated Pastèque implementation with the LLVM backend in comparison to the original Pastèque implementation targeting Standard ML \cite{pac-2024} and the efficient Pacheck \cite{pac-2024} checker written in C++.

As the main benchmark, I use the experimental data presented on the original webpage \cite{pacheck_pasteque} for the evaluation.
The dataset consists of different multiplier circuits with different bit-widths, ranging from 32-bit multipliers to 512-bit multipliers.
I use the current version of the AMulet tool by Kaufmann \cite{amulet2} which decides the given multipliers to be correct and also generates proof certificates in the PAC format.
The resulting certificates are then checked by Pastèque with both the LLVM and Standard ML backend and by Pacheck.
I measure wall-clock time and peak resident set size (RSS) for all checkers using GNU time \cite{gnutime}.
Benchmarks are run on a machine with an AMD Ryzen 5 7500F CPU and 32 GB of RAM.
Each benchmark is run five times, the shown measurements are the respective mean values over all five runs.

Figure~\ref{fig:checker-comparison} shows the same average values for wall clock time and peak RSS in a line chart, where the x-axis contains all benchmarks, ordered by wall clock time for Pastèque with the LLVM backend.
The average values show that, for smaller instances, the LLVM backend is faster and consumes less memory (both by about a factor 2) while for the large 512-bit instances, the Standard ML backend is faster and consumes less memory.
Pacheck, as expected, is the fastest checker and consumes the least memory for every benchmark.

To analyze the performance of Pastèque with the LLVM backend, in comparison with the Standard ML backend, especially for the large 512-bit benchmarks, I further break down the execution times of the individual phases of both checkers.
Pastèque with the Standard ML backend already breaks down execution times for
\begin{itemize}
	\item parsing input files,
	\item initialization, i.e., sorting and normalizing all input polynomials,
	\item and checking the proof steps.
\end{itemize}
The time spent on garbage collection is also measured separately to obtain runtime without garbage collection.
For the LLVM variant, I recreated the outer LLVM main function in C to obtain the same measurement with breakdown into the separate phases.
