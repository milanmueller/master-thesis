\section{Evaluation}\label{sec:evaluation}

This section discusses the evaluation of the migrated Pastèque implementation with the LLVM backend in comparison to the original Pastèque implementation targeting Standard ML \cite{pac-2024} and the efficient Pacheck \cite{pac-2024} checker written in C++.

For the Standard ML backend, Pastèque offers a \inlinecode{uloop} flag with which the outer main loop is replaced by an untrusted version where parsing and checking are interleaved, improving runtime and reducing memory usage \cite{pac-2024}.
As the LLVM backend behaves like the default version of the Standard ML backend (without the \inlinecode{uloop} flag) with parsing and checking being entirely separate steps, I do not use the \inlinecode{uloop} flag in any benchmark.
It should be noted that a \inlinecode{uloop} variant could also be implemented for the LLVM backend, but it would also increase the amount of trusted code to include an outer, unverified main loop.

\subsection{Comparison of all Checkers}\label{sec:comparison-of-all-checkers}

As the main benchmark, I use the experimental data presented on the original PAC webpage \cite{pacheck_pasteque} for the evaluation.
The dataset consists of different multiplier circuits with different bit-widths, ranging from 32-bit multipliers to 512-bit multipliers.
I use the current version of the AMulet tool by Kaufmann \cite{amulet2} which decides the given multipliers to be correct and also generates proof certificates in the PAC format.
The resulting certificates are then checked by Pastèque with both the LLVM and Standard ML backend and by Pacheck.
I measure wall-clock time and peak resident set size (RSS) for all checkers using GNU time \cite{gnutime}.
Benchmarks are run on a machine with an AMD Ryzen 5 7500F CPU and 32 GB of RAM.
Each benchmark is run ten times, the shown measurements are the respective mean values over all ten runs.

The average values show that, for smaller instances, the LLVM backend is about 1.5 to 2 times faster and consumes less memory while for the large 512-bit instances, the Standard ML backend is faster and also consumes less memory in the "sparrc-512" benchmark.
Pacheck, as expected, is the fastest checker and consumes the least memory for every benchmark.
